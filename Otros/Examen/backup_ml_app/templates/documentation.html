1. Objetivo del Proyecto

El objetivo principal de este proyecto es desarrollar un sistema inteligente para reducir el número de jobs de backup con error mediante el uso de técnicas de Machine Learning.

Objetivos Específicos:
  • Analizar patrones en los datos históricos de jobs de backup
  • Identificar factores que contribuyen a los fallos
  • Desarrollar modelos predictivos para anticipar fallos
  • Crear una aplicación web interactiva para visualización y predicción
  • Proporcionar recomendaciones para optimizar la programación de jobs

2. Definición del Problema

Los sistemas de backup corporativos enfrentan varios desafíos que pueden resultar en fallos de jobs:

Problemas Identificados:
  • Fallos impredecibles en jobs de backup
  • Pérdida de ventanas de backup
  • Recursos insuficientes durante la ejecución
  • Configuraciones subóptimas
  • Falta de monitoreo predictivo
Impacto Empresarial:
  • Riesgo de pérdida de datos
  • Incumplimiento de SLAs
  • Costos operativos elevados
  • Tiempo de administración aumentado
  • Reducción de la confiabilidad del sistema

Variables Principales:
Variable Descripción Tipo

5. Preprocesamiento de Datos

Técnicas Aplicadas:
Limpieza de Datos:
  • Eliminación de registros duplicados
  • Tratamiento de valores faltantes
  • Normalización de formatos
  • Validación de consistencia
Ingeniería de Features:
  • Extracción de hora y día de la semana
  • Categorización de velocidades y tamaños
  • Codificación de variables categóricas
  • Normalización de variables numéricas
Variable Objetivo:

Se creó la variable has_error que identifica jobs con problemas (aquellos que no están en estado "Active" o "Queued").

Código de Ejemplo: 
df['has_error'] = ~df['State'].isin(['Active', 'Queued'])

6. Modelos de Machine Learning

Algoritmos Implementados:
Random Forest

Ensemble de árboles de decisión que reduce el overfitting y mejora la generalización.

Hiperparámetros:
  • n_estimators: 100
  • max_depth: 10
  • random_state: 42
Gradient Boosting

Construye modelos de forma secuencial, donde cada uno corrige errores del anterior.

Hiperparámetros:
  • max_depth: 5
  • learning_rate: 0.1
  • random_state: 42
Logistic Regression

Modelo lineal interpretable que sirve como baseline para comparación.

Hiperparámetros:
  • max_iter: 1000
  • random_state: 42
  • solver: liblinear
Justificación de Selección:
  • Random Forest: Maneja bien datos categóricos y numéricos mezclados
  • Gradient Boosting: Excelente rendimiento en problemas de clasificación
  • Logistic Regression: Proporciona interpretabilidad y baseline

7. Evaluación de Modelos

Métricas Utilizadas:
  • Accuracy: Proporción de predicciones correctas
  • Precision: VP / (VP + FP)
  • Recall: VP / (VP + FN)
  • F1-Score: Media armónica de precision y recall
División de Datos:
• 80% Entrenamiento
• 20% Prueba
• Estratificación por variable objetivo
Proceso de Validación:
  1. División estratificada de datos
  2. Entrenamiento de múltiples modelos
  3. Evaluación en conjunto de prueba
  4. Selección del mejor modelo basado en F1-Score
  5. Análisis de matrices de confusión
