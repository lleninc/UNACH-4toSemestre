1.1 · CONCEPTO
Concepto y Tipos de ML
▼
Definición ISO (2023): El aprendizaje automático desarrolla algoritmos capaces de mejorar su desempeño en tareas específicas a partir de datos, sin ser programados explícitamente para cada caso.
vs Programación tradicional: Programación → el humano escribe las reglas. ML → el algoritmo aprende las reglas a partir de los datos.
🏷️
1. Supervisado
Datos con etiquetas conocidas. El más usado.

Ej: spam, diagnóstico médico, predicción de precios.
🔍
2. No Supervisado
Sin etiquetas. Descubre estructuras ocultas.

Ej: clustering de clientes, PCA, análisis de redes.
🔀
3. Semi-supervisado
Pocos etiquetados + muchos sin etiquetar.

Ej: genómica, Google Photos.
🎮
4. Por Refuerzo
Recompensas y penalizaciones al interactuar con entorno.

Ej: robot caminando, videojuegos.
🧠
5. Auto-supervisado
Genera sus propias etiquetas desde los datos.

Ej: GPT, BERT, LLMs.
🔗
Sistemas Híbridos
Combinan múltiples paradigmas. Arquitecturas más robustas y versátiles.

TIPOS DE ML
  • ML aprende patrones sin código explícito — diferencia fundamental con programación tradicional basada en reglas fijas.
  • Supervisado = pares entrada→salida con etiquetas conocidas. Ejemplo clásico: filtro de spam. Se entrena con pares entrada-salida.
  • No supervisado = sin etiquetas, descubre estructura oculta. Ejemplo: clustering de clientes, PCA.
  • Semi-supervisado = pocos etiquetados + muchos sin etiquetar. Ejemplo: Google Photos (reconocimiento de rostros).
  • Por refuerzo = agente aprende a caminar, jugar, tradear. Recompensas (+) y penalizaciones (−). Sin etiquetas predefinidas.
  • Auto-supervisado = genera sus propias etiquetas desde los datos. Base de GPT, BERT y LLMs.
  • Sistemas híbridos = combinan múltiples paradigmas para mayor robustez.
HISTORIA
  • El término "IA" surgió en los 1950s (Dartmouth 1956, John McCarthy). No 1940, no 1980.
  • Resurgimiento IA en 2000s = mayor poder computacional + Big Data.
  • Hito en 2010s = éxito de redes profundas en visión y lenguaje (AlexNet 2012, Transformers 2017).
  • Reglas lógicas en todo sistema = era 1980-1990s, NO los 2010s.
APLICACIONES Y DESAFÍOS
  • Calidad > Cantidad. 80% del trabajo en ML es preparación de datos. "GIGO — Garbage In Garbage Out".
  • Civil/ambiental → predice deslizamientos e inundaciones. No traduce textos ni genera multimedia.
  • ML en educación → adapta contenidos al desempeño del estudiante. No sustituye al profesor.
  • Transparencia en medicina → para que médicos y pacientes comprendan las decisiones del modelo.
  • Complejidad computacional → modelos profundos necesitan GPU/TPU y alto consumo energético.
  • XAI busca transparencia en decisiones. Crítico en medicina y finanzas.
  • Un falso negativo en salud = no detectar una enfermedad en un paciente que sí la tiene.
HERRAMIENTAS Y MATEMÁTICAS
  • Pandas ≠ deep learning. TensorFlow/PyTorch = redes profundas. Pandas = DataFrames tabulares. No renderiza 3D.
  • NumPy = arreglos numéricos. No hace modelos ni visualización por sí solo.
  • Scikit-learn = ML clásico (fit/predict/score). No hace deep learning.
  • Jupyter = documentación reproducible. Colab = Jupyter en la nube con GPU gratis. Sí permite compartir proyectos.
  • Python es preferido por productividad + comunidad + librerías. Sí depende de bibliotecas externas.
  • MLOps = ingeniería de software + ciencia de datos para producción (Symeonidis et al., 2022).
  • Modelos de Markov = probabilidad aplicada a procesos estocásticos y secuenciales. NO deterministas, NO solo álgebra lineal.
  • Los 3 pilares juntos (álgebra lineal + probabilidad + estadística) permiten diseñar algoritmos robustos y generalizables.

2.1 · U1 T2 S3
Flujo de un Proyecto de ML
▼
Idea central: el flujo NO es lineal. Se vuelve a etapas anteriores cuando los datos son malos, la métrica es baja o el modelo no generaliza. Definir el problema siempre va primero.
EtapaQué se hacePor qué importa
1. Definir problema¿Qué predecir? ¿Qué métrica usar?Evita construir un modelo para una meta ambigua
2. Explorar datos (EDA)Patrones, errores, distribuciones, variables claveEntiende la calidad real del dataset
3. PreprocesarFaltantes, ruido, escalado, codificaciónMejora la calidad de entrada al modelo
4. Dividir datosTrain / Val / Test (estratificar si es necesario)Evita evaluar con datos ya vistos
5. EntrenarEl algoritmo aprende relacionesConstruye el modelo
6. Validar y tunearAjustar hiperparámetros con CVElige la mejor versión del modelo
7. EvaluarMétricas sobre datos de pruebaMide el desempeño real (una sola vez)
8. Desplegar y monitorearModelo en producciónConvierte el modelo en una solución útil
🏋️
Entrenamiento
Aprende patrones. Ajusta parámetros del modelo. El 80% del tiempo se invierte en preparación de datos.
🔧
Validación
Ajusta hiperparámetros y compara modelos. Se usa múltiples veces. NO es el conjunto final.
🎯
Prueba
Se usa UNA SOLA VEZ al final. Estima el desempeño con datos completamente nuevos. Nunca para ajustar.
📋
Gobernanza
Trazabilidad, gestión de riesgos (NIST AI RMF), control de fugas de información, versionado y pipelines reproducibles.
NIST AI RMF: Marco de gestión de riesgos para IA. Función MAP → mapear riesgos y supuestos. MEASURE → medir. MANAGE → gestionar. GOVERN → gobernar.

2.2 · U1 T2 S3
Métricas de Evaluación — Clasificación y Regresión
▼
Matriz de confusión:
VP = predijo positivo, era positivo ✓  |  VN = predijo negativo, era negativo ✓
FP = predijo positivo, era negativo ✗  |  FN = predijo negativo, era positivo ✗
MÉTRICAS DE CLASIFICACIÓN
🎯
Accuracy
(VP+VN) / Total

Útil solo con clases balanceadas.
Con 95% negativos, predecir siempre negativo da 95% accuracy → engañoso.
🔬
Precision
VP / (VP + FP)

¿De los que predije positivos, cuántos lo eran?
Útil cuando FP es costoso.
Ej: spam → no marcar correos legítimos.
🩺
Recall (Sensibilidad)
VP / (VP + FN)

¿De los positivos reales, cuántos detecté?
Útil cuando FN es costoso.
Ej: medicina → no perder enfermos.
⚖️
F1-score
2·(Precision·Recall)/(Precision+Recall)

Media armónica entre precision y recall.
Ideal con datos desbalanceados.
Alta precision + bajo recall → muchos FN, pocos FP.
📈
AUROC / AUPRC
ROC-AUC: área bajo la curva ROC. En multiclase usar enfoque "uno contra todos".
AUPRC: mejor para datasets muy desbalanceados.
🎲
Log-loss / Kappa
Log-loss: penaliza predicciones incorrectas con alta confianza.
Kappa de Cohen: acuerdo entre predicciones y realidad corrigiendo por azar.
MÉTRICAS DE REGRESIÓN
📉
RMSE
√(Σ(y−ŷ)²/n)
Más bajo = mejor. Penaliza errores grandes.
Solo para regresión, NO clasificación.
📏
MAE
Σ|y−ŷ|/n
Error absoluto medio. Más robusto a outliers que RMSE.
R²
R² (Coef. determinación)
Proporción de varianza explicada por el modelo.
R²=1 → ajuste perfecto. R²=0 → no mejor que la media.
MétricaTipoCuándo usarCuándo NO usar
AccuracyClasificaciónClases balanceadasDatos desbalanceados
PrecisionClasificaciónFP costosos (spam, alertas)FN más costosos que FP
RecallClasificaciónFN costosos (medicina, fraude)FP más costosos que FN
F1-scoreClasificaciónDesbalance de clasesCuando solo importa una métrica
RMSE / MAERegresiónValores continuosProblemas de clasificación
Weighted average en multiclase: Pondera cada clase según su proporción en el dataset. Usa "uno contra todos" para extender ROC-AUC a multiclase.
Ajuste del umbral: El umbral de decisión (por defecto 0.5) puede ajustarse según los costos del dominio. En medicina → bajar umbral para priorizar recall. En spam → subir umbral para priorizar precision.

2.3 · U1 T2 S4
Validación Cruzada, División de Datos y Data Leakage
▼
DIVISIÓN DE DATOS
DivisiónProporcionesCuándo usar
Train / Test80 / 20Casos simples o datasets pequeños
Train / Val / Test70 / 15 / 15Proyectos académicos y prototipos
Train / Val / Test60 / 20 / 20Cuando se quiere validación más clara
Estratificación: Al dividir, mantener la proporción de clases en cada subconjunto. Importante en datasets desbalanceados para que cada split sea representativo.
K-FOLD CROSS-VALIDATION
Proceso K-Fold:
1. Divide el dataset en K pliegues (folds)
2. Entrena en K-1 pliegues
3. Valida en el pliegue restante
4. Repite K veces rotando el pliegue de validación
5. Promedia los resultados → estimación más estable
✅
Ventajas K-Fold
Usa mejor todos los datos disponibles. Da estimación más estable y robusta. Reduce riesgo de una división afortunada o desafortunada.
⚠️
Desventajas K-Fold
Requiere más tiempo de cómputo (K× más entrenamientos). Costoso con modelos complejos o datasets muy grandes.
🔁
CV Anidada (Nested CV)
Bucle interno: tuning de hiperparámetros. Bucle externo: evaluación honesta del modelo. Evita sesgo en la selección de hiperparámetros.
DATA LEAKAGE — FUGA DE INFORMACIÓN
¿Qué es? Uso indebido de datos de validación/prueba o del futuro en el entrenamiento. Produce evaluaciones optimistas que no se reproducen en producción.
🚨
Cómo ocurre
· Usar datos de test para seleccionar hiperparámetros
· Escalar con estadísticas del dataset completo (antes de dividir)
· Incluir features del futuro en series temporales
🛡️
Cómo evitarlo
· Encapsular preprocesos dentro del pipeline de entrenamiento
· Nunca tocar el conjunto de prueba hasta el final
· Usar CV anidada para tuning honesto
Regla de oro: El conjunto de PRUEBA se usa UNA SOLA VEZ al final. Usarlo para ajustar hiperparámetros = fuga de información = evaluación optimista no reproducible.
⚖️
2.4 · U1 T2 S4
Sobreajuste, Subajuste y Dilema Sesgo-Varianza
▼
SituaciónError TrainError Val/TestCausaSesgo/Varianza
✅ Buen ajusteBajoBajoModelo adecuadoBalance óptimo
🔴 SobreajusteMuy bajoAltoModelo demasiado complejoVarianza alta
🟡 SubajusteAltoAltoModelo demasiado simpleSesgo alto
🔴
Sobreajuste (Overfitting)
El modelo memoriza el ruido del entrenamiento en lugar de aprender patrones generales.

Diagnóstico: error train muy bajo, error val/test alto.

Técnicas para mitigar:
· Regularización L1 (Lasso) / L2 (Ridge)
· Early stopping
· Dropout (redes neuronales)
· Validación cruzada
· Más datos de entrenamiento
· Reducir complejidad del modelo
· Ensembles (bagging)
🟡
Subajuste (Underfitting)
El modelo es demasiado simple para capturar la estructura de los datos.

Diagnóstico: error train alto Y error val/test alto.

Técnicas para mitigar:
· Usar modelo más expresivo / complejo
· Añadir más variables (features)
· Entrenar más tiempo (más epochs)
· Reducir regularización excesiva
· Mejorar preprocesamiento de datos
· Ensembles (boosting)
Dilema Sesgo-Varianza:
· Sesgo alto = subajuste = modelo muy rígido/simple
· Varianza alta = sobreajuste = modelo muy flexible/complejo
· El objetivo es encontrar el punto de equilibrio óptimo
· Regularización, validación cruzada y ensembles ayudan a encontrarlo
Curvas de aprendizaje: Graficar error de entrenamiento y validación vs. tamaño del dataset o epochs. Si el gap es grande → sobreajuste. Si ambas son altas → subajuste. Herramienta clave para diagnóstico.
Manejo del desbalance de clases: class_weights (penaliza la clase mayoritaria), SMOTE (sobre-muestrea la clase minoritaria), re-muestreo. Siempre aplicar dentro del pipeline de CV para evitar leakage.

FLUJO DE PROYECTO
  • El flujo de ML NO es lineal — se itera cuando los datos son malos o las métricas son bajas.
  • Secuencia correcta: definir problema → preparar datos → entrenar → validar → evaluar. Nunca al revés.
  • Función MAP en NIST AI RMF → mapear riesgos y supuestos en el diseño.
MÉTRICAS
  • Accuracy puede engañar con datos desbalanceados → usar F1, Recall o métricas balanceadas.
  • Con accuracy=0.95 en dataset 95% negativo → el modelo puede estar ignorando todos los positivos.
  • Precision → FP costosos (spam, alertas falsas). Recall → FN costosos (medicina, fraude).
  • Alta precision + bajo recall = muchos FN y pocos FP (modelo muy conservador).
  • F1 = 2·(P·R)/(P+R). Media armónica. Ideal con datos desbalanceados.
  • RMSE / MAE / R² → solo para regresión (valores continuos), no clasificación.
  • Log-loss penaliza predicciones incorrectas realizadas con alta confianza.
  • Kappa de Cohen: acuerdo entre predicciones y realidad corrigiendo por azar.
  • ROC-AUC multiclase → enfoque "uno contra todos" para cada clase.
  • Falso positivo (FP) = predicho positivo siendo negativo. Falso negativo (FN) = predicho negativo siendo positivo.
  • En medicina, es más grave no detectar un positivo (FN) que generar una alarma falsa (FP) → priorizar recall.
  • Patrón sistemático en errores → indica sesgo en datos o en el modelo.
VALIDACIÓN Y SOBREAJUSTE
  • Conjunto de prueba = se usa una sola vez al final. Jamás para ajustar hiperparámetros.
  • Usar el conjunto de prueba para seleccionar hiperparámetros = fuga de información → evaluación optimista.
  • K-Fold: divide en K pliegues y rota el pliegue de validación en cada iteración.
  • CV anidada: bucle interno para hiperparámetros + bucle externo para evaluación honesta.
  • Sobreajuste: error train muy bajo + error val alto → varianza alta → regularización, dropout, más datos.
  • Subajuste: error alto en train Y val → sesgo alto → modelo más complejo, más features, menos restricciones.
  • Limitar la máxima profundidad del árbol (max_depth) es el parámetro clave para evitar sobreajuste en árboles.
  • Dropout desactiva aleatoriamente neuronas durante entrenamiento para reducir sobreajuste en redes.
  • SMOTE y class_weights para manejar desbalance → siempre dentro del pipeline de CV, no antes.

Regresión Lineal, Polinómica y Regularizada
▼
REGRESIÓN LINEAL
Propósito: Estimar una variable de salida ŷ como combinación lineal de un conjunto de predictores x₁, x₂, ..., xₚ. El ajuste se logra minimizando el error cuadrático medio (MSE).
ŷ = β₀ + Σ βⱼ xⱼ   donde β₀ = intercepto, βⱼ = coeficientes
Solución matricial: β = (XᵀX)⁻¹ Xᵀy  (requiere que X tenga rango completo)
📌
Interpretabilidad
Los coeficientes muestran cómo cambia ŷ por cada unidad de cambio en cada predictor. Fácil de comunicar.
⚠️
Supuestos
Relaciones lineales · Independencia de errores · Homocedasticidad (varianza constante) · Normalidad de residuos
REGRESIÓN POLINÓMICA
¿Cuándo usarla? Cuando la relación entre variables NO es lineal. Amplía la expresividad introduciendo potencias de los predictores (x², x³, ..., xⁿ).
ŷ = β₀ + β₁x + β₂x² + β₃x³ + ... + βₙxⁿ
✅
Ventaja
Permite capturar curvaturas y tendencias complejas que el modelo lineal simple no puede representar.
🔴
Riesgo
Incrementar el grado genera sobreajuste. Tensión sesgo-varianza: bajo grado = alto sesgo, alto grado = alta varianza.
REGULARIZACIÓN — RIDGE Y LASSO
¿Para qué sirve? Estrategia esencial para controlar la complejidad del modelo y evitar sobreajuste. Añade una penalización a la función de pérdida.
🔵
Ridge — L2
Penaliza suma de cuadrados de coeficientes:
Minimiza: RSS + λ Σ β²ⱼ

→ Encoge los coeficientes (los reduce)
→ No anula coeficientes
→ Útil frente a colinealidad
🔴
Lasso — L1
Penaliza suma de valores absolutos:
Minimiza: RSS + λ Σ |βⱼ|

→ Puede anular coeficientes
→ Actúa como selector de variables
→ Produce modelos más interpretables
Hiperparámetro λ (lambda):
· Controla la intensidad de la penalización
· Se ajusta mediante validación cruzada
· λ = 0 → sin penalización → regresión lineal clásica
· λ grande → más penalización → mayor sesgo, menor varianza
· λ pequeño → menos penalización → menor sesgo, mayor varianza
MétodoPenalizaciónAnula β?Uso ideal
Lineal clásicaNinguna (λ=0)NoDatos sin colinealidad ni sobreajuste
Ridge (L2)Σ β²ⱼNoColinealidad entre predictores
Lasso (L1)Σ |βⱼ|SíSelección automática de variables

Regresión Logística y Softmax
▼
REGRESIÓN LOGÍSTICA BINARIA
Diferencia clave: A diferencia de la regresión lineal, la logística está diseñada para resolver problemas de clasificación, no de predicción de valores continuos.
P(y=1|X) = σ(wᵀx + b) = 1 / (1 + e⁻⁽ʷᵀˣ⁺ᵇ⁾)
σ
Función Sigmoide
σ(z) mapea cualquier valor real al intervalo [0,1]. Interpreta la salida como probabilidad de pertenecer a la clase positiva.
⚖️
Parámetros
w = vector de pesos (coeficientes). b = sesgo (bias / intercepto). Los coeficientes se interpretan en términos de log-odds.
Función de pérdida — Entropía cruzada:
L(w) = -Σ [ y log(ŷ) + (1-y) log(1-ŷ) ]
Se minimiza mediante optimización iterativa (gradient descent).
NO es el error cuadrático medio (MSE).
Muy valorada en: ciencias de la salud, economía y marketing por su interpretabilidad y capacidad de generar probabilidades de clasificación.
SOFTMAX — CLASIFICACIÓN MULTICLASE
¿Cuándo usarlo? Cuando el problema incluye más de dos clases (K > 2). Softmax generaliza la regresión logística binaria.
P(y=k|X) = e^(wₖᵀx + bₖ) / Σⱼ e^(wⱼᵀx + bⱼ)   para j = 1 a K
📊
Salida en vector
Cada observación recibe un vector de probabilidades que suma exactamente 1. Se asigna la clase con mayor probabilidad.
🧠
Uso en Redes Neuronales
Es la capa de salida estándar en redes neuronales para clasificación multiclase. Gran eficacia en imágenes y texto.

U2 T2 · SVM
Máquinas de Soporte Vectorial (SVM)
▼
Objetivo: Buscar el hiperplano de máximo margen entre clases. Los vectores de soporte son los puntos más cercanos al hiperplano — son los que definen y determinan la frontera de decisión.
f(x) = wᵀx + b   → distancia con signo al hiperplano
⚙️
Hiperparámetro C
Controla el trade-off margen/errores.
C grande → penaliza más errores → margen estrecho → riesgo sobreajuste.
C pequeño → margen amplio → más errores tolerados.
🌐
Kernels
Permiten separar datos no lineales:
· Lineal: datos linealmente separables
· Polinomial: relaciones polinómicas
· RBF: fronteras complejas (más usado)
· Sigmoide: relacionado con neuronas artificiales
🎯
Gamma (γ) en RBF
Controla influencia local de cada muestra.
γ alto → fronteras muy onduladas/localizadas → sobreajuste
γ bajo → fronteras suaves → mejor generalización
Ajustar C y γ siempre con validación cruzada.
¿Cuándo usar SVM? Con datasets pequeños/medianos y cuando la interpretabilidad importa. Para datasets grandes y complejos → redes neuronales.

U2 T2 · MLP
Redes Neuronales (MLP) — Backpropagation y Optimización
▼
Neurona artificial: Calcula una suma ponderada de entradas más un sesgo (b), luego aplica una función de activación.
z = Σ wᵢxᵢ + b   →   salida = f(z)
FUNCIONES DE ACTIVACIÓN
⚡
ReLU (estándar moderno)
ReLU(x) = max(0, x)
Eficiente computacionalmente.
Evita el problema del gradiente evanescente.
Estándar en capas ocultas de redes profundas.
σ
Sigmoide
σ(z) = 1/(1+e⁻ᶻ) → salida en [0,1].
Estándar en clasificación binaria (capa de salida).
Problema: gradiente evanescente en capas profundas.
🔄
Tanh
Salida en [-1, 1]. Centrada en 0.
Mejor que sigmoide para capas ocultas.
También sufre gradiente evanescente.
📊
Softmax (salida)
Probabilidades normalizadas que suman 1.
Estándar en clasificación multiclase (capa de salida).
Compatible con entropía cruzada como pérdida.
ENTRENAMIENTO
↩️
Retropropagación (Backprop)
Calcula gradientes de la función de pérdida respecto a cada parámetro usando la regla de la cadena. Permite actualizar pesos en cada capa.
📉
Optimizadores
SGD: descenso de gradiente estocástico (clásico).
Adam: adaptativo, más robusto que SGD. Estándar en la práctica.
Requieren escalado previo de las entradas.
REGULARIZACIÓN EN REDES
💧
Dropout
Desactiva aleatoriamente neuronas durante entrenamiento. Reduce sobreajuste. En inferencia todas las neuronas están activas.
⏹️
Early Stopping
Detiene el entrenamiento cuando la métrica de validación deja de mejorar. Evita sobreajuste sin modificar la arquitectura.
⚖️
Weight Decay (L2)
Penaliza pesos grandes durante el entrenamiento. Equivalente a regularización Ridge en redes neuronales.
El perceptrón simple NO puede resolver el problema XOR — no es linealmente separable. Se necesitan redes multicapa (MLP) con funciones de activación no lineales.
Función de pérdida en clasificación: Entropía cruzada (cross-entropy). NO el MSE (que es para regresión).

U2 T2 · ÁRBOLES
Árboles de Decisión — Entropía, Gini y Poda
▼
Estructura: Nodos internos = condiciones sobre variables. Hojas = predicciones finales. El árbol divide recursivamente el espacio de características.
CRITERIOS DE DIVISIÓN
📊
Entropía
H(X) = -Σ p(x)·log₂p(x)

Mide el nivel de incertidumbre de la distribución de clases.
H=0 → nodo puro (una sola clase)
H=1 → máxima mezcla (50/50 binario)
El árbol busca cortes que maximicen la Ganancia de Información.
📐
Índice de Gini
Gini = 1 - Σ p²(k)

Gini ≈ 0 → partición homogénea (nodo puro)
Gini ≈ 0.5 → máxima mezcla (binario)
Computacionalmente más eficiente que la entropía en la práctica.
ValorEntropíaGiniSignificado
Nodo puro (100% una clase)00Sin incertidumbre → hoja
Mezcla máxima (50/50)10.5Máxima incertidumbre
Mezcla parcial0 a 10 a 0.5Incertidumbre parcial
SOBREAJUSTE Y SUBAJUSTE EN ÁRBOLES
🔴
Árbol muy profundo → Sobreajuste
Aprende el ruido del entrenamiento. La capacidad de generalización se reduce. Sin poda → captura ruido → overfitting.
🟡
Árbol muy poco profundo → Subajuste
Baja profundidad + alto error en entrenamiento = subajuste. No aprende patrones suficientes → underfitting.
Poda: Reduce ramas innecesarias para mejorar la generalización. Pre-poda (max_depth, min_samples_split) controla la complejidad antes de crecer. Post-poda (ccp_alpha) recorta después.
Dilema sesgo-varianza en árboles: refleja el equilibrio entre simplicidad (poco profundo = sesgo alto) y capacidad de generalización (muy profundo = varianza alta). Se regula con hiperparámetros.
🎯
U2 T2 · ENSEMBLES
Métodos de Conjunto — Bagging, Boosting y Stacking
▼
🌲
Bagging
Reduce varianza. Entrena modelos en muestras bootstrap y promedia.

Ejemplo: Random Forest (árboles con subconjuntos aleatorios de features).
🚀
Boosting
Corrige sesgos. Modelos secuenciales que aprenden de los errores del anterior.

Ejemplos: XGBoost, LightGBM.
🔗
Stacking
Combina predicciones de múltiples modelos usando un meta-modelo.
Mejora estabilidad general pero requiere validación cuidadosa para evitar fugas.
Recomendación práctica: Empezar con modelos simples (regresión lineal, logística, SVM) para establecer una línea base. Escalar a redes o ensembles solo si los datos y el problema lo justifican. Siempre validar con esquemas reproducibles.
